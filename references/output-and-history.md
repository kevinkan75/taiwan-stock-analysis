## 快速版（預設）

以約600–1,000個中文字加必要表格為目標；完整性優先，避免重複。

1. **標頭**：公司、代碼、交易所、普通股／ADR、幣別、分析時間、行情時間及狀態、財報截止日、中長期研究假設、**規則版本 1.14.0**。10個交易日內有法說會、財報或股東會等重大預定事件時，在標頭加「⏰ 判斷時效短：X月X日〔事件〕」。
2. **專家摘要四行**：固定順序與欄名為「估值位置、下一個催化劑、最大單一風險、關鍵缺口」，詳下方「摘要共同規則」；放在燈號表之前，四行均不得省略。
3. **一眼結論**：整體投資訊號（含暫定與信心等級）＋2句理由，先寫已確認的結論，再寫尚未確認的部分及下一個驗證條件。新模型定稿保留portability「報告文字與版本追溯」規定的單一結果行，燈號、總分、暫定與信心須與快照相符。R6敏感度檢查翻轉燈號時加「⚠ 結論脆弱：〔分項〕改為X分時，燈號變為Y」；R4有限制導致信心下調時一併寫明。整體⚪時保留分項證據摘要，例如「營運證據偏強，現價吸引力尚未確認」，不另給綜合訊號。小表列基本面、成長性、估值、產業趨勢、技術面、風險，含燈號、一句依據；已評分者保留面向分與覆蓋數，標為自訂研究分、非勝率。總分僅符合門檻時顯示。
4. **核心數據**：股價（附52週高低價及距高點幅度）、市值、EPS、P/E（另列forward P/E及來源）、營收成長、EPS成長、ROE、毛利率、自由現金流及現金殖利率；產業關鍵指標另列1–2列。另依financial-history.md呈現三個完整年度趨勢與勾稽狀態，季度及TTM另列、不補成年度；快速版可將完整年度附表放於同一交付報告的附錄，保留會影響判斷的缺口。每列數值、期間／口徑及來源。缺漏寫未取得，不適用寫原因或替代指標。
5. **投資邏輯與估值**：值得關注的原因與市場關注議題、2–3項動能、1項失效條件；保守／基準／樂觀情境表（假設、模型價、相對現價）及假設來源。分開已知事實、公司說法、外部預估及分析推論；「市場正在交易什麼」若無證據，標為可能解讀。無合適資料就以已知估值及缺口替代。
6. **最新事件與風險**：2–3項最影響判斷的事件及2–3項具體風險，附日期與來源。
7. **與上次比較**：可用時列3–6個重要變化；無前次就一句說明。
8. **下一步觀察**：2項可改變判斷的條件。需要時附一句「研究判斷，非獲利保證」。

技術面預設不展開詳細資料。介面支援真實收合時放預設收合區；否則保留一句摘要並標「可要求展開技術面」。不要假稱Markdown介面有收合功能。

技術面狀態須依實際執行結果區分，不能僅因快速版就假稱已計算：

| 狀態 | 顯示方式 |
| --- | --- |
| 已取得240筆以上有效日線並完成計算、只省略明細 | 「已計算，未展開」；可依scoring.md顯示技術燈號。 |
| 快速模式尚未執行取數或計算 | 「⚪未計算（快速模式未執行）」；不填技術分數或趨勢。 |
| 已嘗試取數／計算，但序列不足240筆或資料無法核對 | 「⚪資料不足」及具體缺口；已計算指標可列示並標「樣本不足，僅供參考」，不形成完整技術燈號。 |

任何模式都保留影響結論的EPS替代口徑、估算市值及估值假設限制；把公式、長表與評分證據移至詳細版，不能把限制一起隱藏。

ETF模式的快速版模板見etf.md「ETF快速版輸出」；市場模式的輸出與存檔格式見market.md「市場快照輸出與存檔格式」。

## 摘要共同規則

個股與ETF的快速版、詳細版、聚焦模式及決策模式均使用下列四行，固定順序與欄名；其他模板引用本節，不另定例外。市場快照及只出結構說明、不評分的工具使用專屬模板，不要求這四行。

| 欄名 | 必填內容與缺值寫法 |
| --- | --- |
| 估值位置 | 現價倍數、歷史／同業位置與依據；R3衝突並列主、交叉方法。資料不足寫「未取得：〔項目及影響〕」，不以無依據倍數補成合理價。 |
| 下一個催化劑 | 已確認日期、事件及要觀察的數字；ETF可填換股、除息或主要持股財報。事件尚未確認寫「尚未確認：〔待查事件或日期〕」，不得編造日期。 |
| 最大單一風險 | 一項具體風險及傳導路徑；尚未完成查核寫「未完成風險核對：〔範圍〕」，不得寫成沒有風險。 |
| 關鍵缺口 | 最重要的未取得資料及其影響；已完成核對且未發現關鍵缺口時寫「本次核對範圍內未發現影響判斷的關鍵缺口」，不得省略或泛稱資料完整。 |

聚焦模式下，未列入本次範圍的欄位填「本次未評估」；已嘗試但拿不到資料仍填「未取得」及原因，兩者不可互換。摘要不得產生正文與快照沒有的數據、燈號或信心；研究訊號與進場／分批／等待／放棄行動結論分別標示。四行以獨立文字行呈現，例如`- **估值位置：** …`，不合併為一段或移至表格。

新個股定稿由snapshot_guard檢查四個欄名按序出現一次且非空；只驗證格式存在，內容、事實及與正文的語意一致性仍人工核對。ETF與聚焦紀錄不交個股驗證器，依同格式人工核對。

## 聚焦模式

只要求單一面向（技術面、估值、基本面等）時使用。輸出順序：

1. **標頭**：同個股快速版（含規則版本、⏰判斷時效短），並加一行「財報核對：已讀完整報表（來源、期間）／未讀（已清空：列出被清空的評分項、指標與估值依據；報告內無上述已知數值或肯定主張，明確缺值聲明可保留）」。
2. **專家摘要四行**：依「摘要共同規則」，未評估與未取得須分開。
3. **指定面向全文**：依該面向的規則展開，其餘面向不評分。
4. **反方審查**：列出最可能的3個原因與處理結果。
5. **資料與限制**：來源、調整方式、驗證範圍、缺口；末行列查詢次數。

聚焦模式不給整體投資訊號與綜合燈號；使用者之後要完整分析時另行補做。純技術面時，估值與基本面的提醒最多一句背景說明，不替它們下判斷。

聚焦模式的結構化紀錄（第一階段，不交snapshot_guard）：技術面聚焦存 `snapshot_type: "technical"`、`model_version: "rule-1.3"`、`validated: false`，欄位如下，其餘面向聚焦比照辦理並改 `snapshot_type`：

```json
{
  "snapshot_type": "technical",
  "model_version": "rule-1.3",
  "validated": false,
  "security": {"name": "", "symbol": "", "exchange": "", "instrument": "ordinary", "currency": ""},
  "analysis_at": "ISO8601 with offset",
  "data_cutoff_at": "ISO8601 with offset",
  "bars": {"count": 0, "first_date": null, "last_date": null, "source": "", "adjustment": "", "cross_checks": []},
  "indicators": {"sma20": null, "sma60": null, "sma120": null, "sma240": null, "rsi14": null, "macd": null, "macd_signal": null, "macd_histogram": null, "volume_sma20": null, "relative_volume20": null},
  "signal": "unknown",
  "levels": {"support": [], "resistance": []},
  "events": [],
  "data_gaps": [],
  "sources": []
}
```

檔名沿用保存規則，mode 欄填 technical。歷次比較只與同代號、同模型的技術面紀錄比較，或只比完整報告中的技術面欄位。

## 詳細版

保留快速版全部（含R9反方審查：列出最可能的3個原因與處理結果），依序展開：近3–5年及最近季度財務、分部及現金流、動能證據與失效條件、歷史／同業估值、情境與敏感度、技術面期間及價量圖、事件時間軸、風險傳導與觀察指標、歷次比較、評分明細及缺口。

只要求估值、基本面或技術面時聚焦指定部分。多檔比較先給同期間同口徑表，再說差異，保留來源及缺口。

## 歷次比較

- 同一證券、交易所、幣別及一致模型；2330與TSM不能當同一股票的歷次快照。ETF只與同代號、同模型版本的ETF紀錄比較；追蹤同一指數的不同ETF（如0050與006208）不是同一標的。
- 優先使用同一對話中完整可見的前次報告；不足時依可用檔案或個人脈絡技能查找。找同標的最近一次、早於本次截止時間的可用報告，列前後時間。只有摘要時只比其中明確數據，不重建未知細節。
- 先比較證券口徑、model_version及rule_version；模型不同或規則主.次號不同時，分數與燈號僅列示，不判斷改善或惡化。缺任一版本時標「未知／不可直接比較」，不得推定1.2.x或由今日技能版本回填。可用snapshot_guard的`--compare previous.json`檢查已驗證快照。較早報告時間、財務期間及來源口徑仍須人工核對。
- 保存skill_version、rule_version、validator_version；schema_version只表示格式，不能單獨證明規則相同。前次reference另存model_version及上述三版本；無法確認者明列null。技能修訂版本不同不必然否決可比性，規則主.次號與模型須相同。
- 優先比實際數據與假設，再比燈號。表格：項目｜前次數值／口徑｜本次數值／口徑｜差額／變動｜對論點影響。
- ↑／↓表示數值方向，判斷改善／惡化另寫。風險增加不是改善，估值倍數下降未必改善。
- 利率、毛利率等以百分點差表示；價格以絕對及百分比變動；EPS同口徑才算百分比。
- 分開行情更新、財報期間滾動、預估修訂、模型假設變更、來源修正及判斷變化。新季度與舊季度比較不宣稱同一期被修正。
- 無前次寫「本次建立比較基準，尚無可用前次報告」，不編造前次燈號。無持久保存不承諾下次自動找到。

## 保存報告與快照

決策模式另存.decision.json，不以它替換原研究JSON；來源雜湊、定稿步驟與ETF人工範圍依decision.md「決策結論程式驗證」。

遵循可用檔案技能；有權限時保存完整報告與JSON快照，沒有就不聲稱保存成功，不阻擋當次報告。

檔名 `股票分析_{market}_{symbol}_{YYYYMMDD-HHMMSS}_{mode}.md`（時間戳取自執行時的當前時間並換算使用者時區，不省略時分秒；保存位置以使用者指定為準，未指定時先查找既有分析資料夾，仍無法判斷就詢問，不預設存根目錄） 與同名`.json`；ETF改用 `ETF分析_` 前綴，JSON依etf.md標validated=false，新快照保留歷史；只有使用者要求修正既有檔案時替換該身份。

市場與產業快照只存JSON：`市場快照_{market}_{YYYYMMDD-HHMMSS}.json`、`產業快照_{market}_{產業}_{YYYYMMDD-HHMMSS}.json`。分析前先在保存位置找最新一份，依market.md與industry-indicators.md判定是否有效；有效才沿用。`capabilities.storage` 依實際可用的保存工具標記，已上傳的舊檔保留原樣不改寫。

市場快照最少欄位見market.md「市場快照輸出與存檔格式」。

產業快照最少欄位：`snapshot_type: "industry"`、`model_version: "market-1.0"`、`validated: false`、`market`、`industry`、`covered_symbols`、`indicators`（每項含name、value、unit、as_of、frequency、source_url）、`policy_and_guidance`、`valid_until`、`valid_until_basis`、`cost_log`、`data_gaps`、`sources`。

個股報告沿用快照時，在報告開頭列快照檔名與日期；報告末行列「本次查詢：搜尋N次、讀取M次；沿用快照：…」。相對強弱與Beta依market.md存為metrics額外鍵。

新研究快照採schema 1.5（model 1.3），發布組合依SKILL.md metadata與rules_core.py，以 `assets/snapshot.example.json` 為底：它是合成資料，可通過 `snapshot_guard --derive`，整體訊號與面向分由程式填入；須把所有範例內容換成實際資料、三項證據與來源，必填欄位不得省略。範例中的分數、燈號與數值只示範格式，不得當作預設或預期結果。欄位細節與驗證出錯時才查 `assets/snapshot.schema.json`，並按 `references/portability.md` 推導及驗證。

`metrics`每項保留資料資源規定的值及來源欄位。`scores`每面向保存三項分數、證據、覆蓋數及原始面向分。`sources`保留URL、文件名稱、發布日期及查閱時間，不能只存會話短引用代碼。只存研究資料，不推測持股、成本或資產。

`technical.status`使用computed／not_run／insufficient_data，只有computed表示完成評燈所需指標；computed須附日期、來源、調整方式、筆數及指標。`validation`逐項保存check、status（pass／limited／fail）、reason及對應metrics；model 1.3須與eligibility狀態一致，financials_verified不設limited。schema 1.5／model 1.3另保存技能／規則／驗證器版本、完整report_markdown、report_sha256及sensitivity；定稿後重算與驗證，報告採同一份有效分、信心與暫定結果。schema 1.4／model 1.2新增估值guardrails與applied_adjustments；schema 1.3／model 1.1增加暫定訊號、信心等級、估值區間與倍數／EPS來源欄位；schema 1.2／model 1.0快照仍可驗證，但不回填這些欄位，也不重算成暫定訊號。讀取舊快照時，新增欄位視為未知，不回填推測值；缺EPS口徑時停用該項成長比較，其餘已確認數據仍可比較。保留舊快照，不批次改寫歷史分數。

previous_report_reference非null時包含reference（可攜來源識別）、analysis_at及schema_version；新模型另保存model_version、skill_version、rule_version、validator_version（未知null）；保存平台頁面等延伸資訊可放report_reference.reference，新模型必須在report_markdown保存完整最終報告文字。不能只存平台內部引用編號。無持久保存時只交付當次內容，不編造保存連結。

## 1.13.0交付補充

完整新個股／ETF報告及決策另執行SKILL.md直接連結的research-process.md；保存共用.review.json及其來源檔雜湊，研究與決策之外再通過review_guard預設驗證。作業狀態、等待原因、取數紀錄及信心追問以該文件為唯一出處；舊紀錄不回填。
