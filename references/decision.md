# 投資前決策檢核

研究層評估公司、價格與風險；決策層再結合時點、事件及可執行條件。研究🟡可得出等待，研究⚪則先補證據。決策層把研究結論轉成行動條件，並在進場前寫好何時認錯。

## 目錄

- 界線與資料來源對照
- 八關與共同判定順序
- 結論規則
- 輸出
- ETF版關卡改寫

## 界線

- 只處理買進與加碼前的判斷；賣出決策、部位金額、資產占比及投資組合配置不在範圍內。
- 不納入使用者個人資金、持股或成本；只給分批節奏與觸發條件。使用者主動提供個人狀況時，可在結論後另加一段說明，但不改變燈號。
- 結論是條件式研究判斷，寫「若…則…」，不寫「會漲」；不用「必買」「穩賺」等字眼。結尾一句「研究判斷，非個人化投資建議」。
- 不改動研究分數與燈號。八關證據仍逐關人工核對；行動結論、首次命中條款、資料連動及必要條件欄位可由decision_guard核對。

研究JSON為只讀參照，不重算scores／overall或新增決策欄位。另保存decision-1.1紀錄及其完整report_markdown，包含研究摘要與決策全文；原研究JSON可保留研究全文，或已綁定同一份定稿。decision_guard核對第2、6、7關數值推導及混合八關的結論、條款與格式，不表示原始證據已自動查證。

## 八關

每關給🟢／🟡／🔴／⚪，附一句證據與來源。⚪＝證據不足，不等於中性，不可用推測補成🟡。

### 共同判定順序

1. 已確認足以構成本關🔴的證據優先，不因另有缺值而遮蔽；未核實的傳聞不構成🔴。
2. 無已確認🔴、但缺判定必要資料時給⚪，不把「未確認」當「無事件」或「風險低」。
3. 資料齊備後按本關互斥條件判定。精確值依含等號區間；近似值或來源衝突可能跨閾值時採較不利一方，揭露理由。第4關維持market.md的R7。
4. 所有關卡完成後只依「結論規則」選一個行動；不得為了行動結論改研究分數或關卡燈號。第8關須區分資料未取得與論點本身不可驗證。

### 1 研究基礎
🟢 整體🟢；🟡 整體🟡；🔴 整體🔴（含重大風險）；⚪ 整體⚪資料不足。整體為暫定訊號時，暫定🔴維持🔴，其餘最高🟡並註明信心等級。

### 2 估值紀律
倍數依據須至少36個月度觀測、資料商公布的3年以上區間（標未自行重算），或3家以上可比同業。只有可靠短樣本但未達上述門檻，最高🟡；資料缺失本身給⚪，不能把「樣本不足」用作缺資料的中性分。研究層估值面向為⚪時，補查只用於本關，不回填研究分數。

按序：🔴 現價倍數位於上緣20%或高於高點，或保守情境下行>30%；⚪ 無可靠倍數／區間位置或保守情境、或口徑轉換未核對；🟢 現價倍數低於區間中位且保守下行≤15%，並滿足樣本門檻；🟡 其餘已可判定情況（含中位、15%<下行≤30%或短樣本）。下行＝max(0,1−保守模型價÷現價)×100%。

上緣20%優先用可核對百分位（≥第80百分位）；資料商只給低／中／高時，以低點＋0.8×(高點−低點)為上緣門檻，標「線性區間近似，非歷史百分位」。低點＝高點時不能以區間位置判紅或綠；若無其他已確認紅燈證據則⚪。恰為15%下行可符合🟢，恰為30%仍🟡；近似跨門檻仍依共同規則採較不利。
金融業用P/B搭配ROE；虧損公司用EV/Sales並說明。

### 3 論點可驗證
🟢 至少2項可量化檢查點（毛利率區間、月營收年增、NIM、CSM等），且有公司指引可對照
🟡 只有1項，或指標存在但無指引可對照
🔴 論點主要依賴題材、市場情緒或單一外部預估
⚪ 研究層尚未形成論點，或已形成論點但缺可核對的檢查點

### 4 市場環境
依市場選指標：
- 台股：加權指數相對240日線乖離、美國10年債殖利率近期方向、外資近5–10日買賣超、成交量異常。
- 美股：S&P 500或Nasdaq相對200日線乖離、VIX水準與方向、美國10年債殖利率近期方向、信用利差或成交量異常。

🔴 已確認兩項以上不利；其餘情況若4項有任一缺值為⚪；4項齊備時，一項不利🟡、零項不利🟢。缺值不當作中性，市場快照依相同完整性判準。

台股優先讀取同一交易日的有效市場快照，依market.md的預設判定與使用前檢查；快照非同一交易日或已失效時重做。燈號只用上列4項，補充指標（匯率、費半、融資、台指VIX、外銷訂單、出口、景氣燈號、族群強弱）只列為說明，不計入不利項目數。邊界值與來源矛盾依market.md「邊界值與來源矛盾（R7）」以較不利一方計入，燈號旁標「含邊界指標」並列「若改判中性則燈號為X」；美股指標同樣適用。市場狀態為「恐慌」時，在本關證據加註「個股相關性升高，大盤主導」。美股第一階段沿用上列指標自行查核。

### 5 事件風險
交易日以該市場交易所行事曆計算，扣除國定假日與補假。事件含財報、法說、除權息、股東會、重大政策或監管期限。
按序：🔴 最近已確認事件距離0–5個交易日，或有已確認、未定案且直接影響論點的政策；⚪ 下次財報日或近期事件查核未完成；🟡 最近事件距離6–10個交易日；🟢 已核對未來10個交易日且無上述事件。多事件取最不利一項。已公布時刻已過且事件確認完成者，評估其結果，不再列未來事件；當日尚未發生者距離為0。公告不能晚於資料截止，事件日可在未來。

### 6 價格位置與動能
優先用研究層已計算指標。否則引用最近3個交易日內的資料商指標，列日期、參數、資料商及「未自行重算」。最低需收盤、SMA20、SMA60、RSI14；趨勢參考線優先SMA120，缺時改SMA60並註明。乖離d＝(收盤÷SMA20−1)×100%，保留正負號。

按序：🔴 已確認RSI14>75或d>15%（過熱），或收盤<趨勢參考線且MACD<訊號線；⚪ 最低指標缺值，或收盤已低於參考線但缺MACD／訊號而不能判斷弱勢；🟢 收盤>SMA60、40≤RSI14<65且|d|<8%；🟡 其餘有足夠資料者。無其他紅燈條件時，RSI恰65／75及乖離恰8%／15%為🟡邊界；SMA60相等不屬🟢。負乖離不解讀為過熱，不因RSI<40自動判便宜。

### 7 預期反映程度
比較過去12個月股價漲幅P與同期同口徑獲利成長G（金融業可用每股淨值成長）。兩者皆用百分比，不把百分點或負成長除成倍數。

| 條件 | 燈號 |
| --- | --- |
| 已確認成長主要來自合併範圍、低基期或一次性項目 | 🔴，說明已確認因素 |
| 缺同口徑原值、基期獲利≤0或近零致百分比失真 | ⚪，列原值／轉盈差額，不計倍數 |
| G>0且P≤G | 🟢 |
| G>0且G<P≤2G | 🟡 |
| G>0且P>2G | 🔴 |
| G＝0且P>0，或G<0且P≥0 | 🔴 |
| G＝0且P≤0，或G<0且P<0 | 🟡，不因股價跌得更多而判🟢 |

先檢查已確認的成長品質問題與可比性，再按數字表判定。G>0時恰為1倍🟢、恰為2倍🟡；零／負成長另走末兩列。ETF按下方第7關直接沿用研究層，不另重算。

### 8 退場條件
三種各至少一條，須可客觀判定：
- 論點型：以研究層失效條件為基礎，具體化為指標與門檻。
- 價格型：有依據的價位（近期低點、SMA120或保守情境模型價）。
- 時間型：多久內論點未兌現就重新評估。

按序：🔴 已取得足夠論點資料，仍只能依賴不可驗證敘事、無法定義論點型失效條件；⚪ 論點尚未形成、來源不足或失效條件因缺資料無法核對；🟢 三種均有可客觀核對的門檻、事件或期限；🟡 已有可核對的論點型條件，但價格型／時間型有任一未齊。資料不足不直接判🔴，也不憑空補價格或數字；具體事件不必強行改寫成數字。

## 結論規則

依序判定，先符合者為準：

1. **放棄**：第1關🔴；或第2關與第3關同時🔴；或第8關🔴。
2. **等待**：無可核對現價、報價時間不明或落後最近完成交易日；或第1、2、3、5、6、8任一關⚪；或第5關🔴；或第5關🟡且第4關🔴；或第2關🔴且第7關🔴；或🔴燈≥3個。
3. **進場**：第1、2、3、5、8關皆🟢；第4、6、7關均為🟢或🟡；全部🔴燈為0。
4. **分批**：其餘已通過核心資料門檻的情況；各批須有具體觸發條件，條件未滿足前不視為立即買入；第6關🔴時，首批須以該關轉為非紅為前提。

第4、7關的⚪不單獨觸發等待，但阻止直接進場；若結論為分批，須將補齊或重新核對該缺口列為批次觸發條件。第8關🟡亦不允許直接進場。放棄表示本次進場方案不成立，不等於永久否定公司；資料不足使用等待。報告列出首次命中的結論條款及缺口，不改燈號迎合直覺。

每個結論都要附：
- **升級條件**：哪些關改善後可往進場方向移動，具體到數字或事件。
- **降級條件**：哪些變化會讓結論變差。
- 分批：批數與每批觸發條件（價格、事件或時間），不寫金額或比例。
- 等待：寫明待取得的文件、可核對事件或有依據的價格條件；未知事件日／價位寫待確認，不為了具體化而編數字。

## 決策結論程式驗證（decision-1.1）

新模式使用scripts/decision_guard.py，單一行動判定為classify；四條順序與上方「結論規則」一致。新紀錄以numeric_inputs推導第2、6、7關，第一關沿用研究；第3、4、5、8關、來源真實性與日曆仍人工。先核對結構化原值，再讓程式產生燈號、行動及報告片段，不改研究分數或補造缺值。decision-1.0歷史紀錄仍只核對結論。

### 輸入與參照

以assets/decision.example.json為格式底，合成內容全部替換；錯誤時才讀assets/decision.schema.json。stock snapshot的schema 1.5不變，決策另存snapshot_type=decision、schema_version=1.1、model_version=decision-1.1。發布與驗證器版本依rules_core.py及SKILL.md metadata。

- research_reference記原研究JSON檔案的SHA-256、來源識別、model_version、rule_version、analysis_at及data_cutoff_at。未知舊規則保留null，不由當前版本回填。--research必須指向實際原檔，程式核對檔案位元組、證券身份、時間及來源版本，來源不可晚於決策。原檔改動須重新核對參照，不默默覆寫雜湊。
- 個股verification=stock_snapshot，原研究須通過snapshot_guard預設驗證；第1關由原overall推導，暫定綠／黃最多黃、紅仍紅，資料不足為白。前次同交易日可沿用，但報價時效仍核對。
- quote_context填最新已完成交易時點latest_completed_session_at、實際核對時間、原因與來源；缺時點保持null。程式不抓日曆；只用已提供且人工確認的交易時點，來源報價未核對、時間不明或早於該時點即等待（已確認放棄條件仍優先）。不同時區按實際時間比較，不能只看日期。
- 來源報價早於最新完成交易時點且已跨當地日期，驗證結果回傳research_refresh_required=true；等待目標可填research或quote並說明更新事項。這只允許保存等待／放棄紀錄，不代表當日研究已完成。日曆、休市及交易時點真實性仍須人工確認。
- gates按1–8排列，每項記number、signal、reason、source_urls；紅黃綠都須有已登錄來源，白燈保留缺口與原因。第2、6、7關由numeric_inputs推導，其餘關卡保留人工核對。
- conditions保存upgrade、downgrade、waiting_for與batches。等待事項填target及具體description；分批至少兩批且各有觸發說明。程式推導first_batch_requirements，第4／7白燈需補齊、第6紅燈須先轉非紅；第一批requires_clearance須包含這些目標。這是條件式方案，不表示立即買入。

ETF新紀錄verification=etf_snapshot時，原檔須為etf-1.1或etf-1.2並validated=true；decision_guard會實際重跑etf_guard預設驗證，不只信任通過旗標。報告保留ETF機械驗證範圍；研究分數與第1關連動，八關證據仍人工。

舊ETF verification=manual_etf時，原研究仍validated=false，另須有可核對的subtype、security、overall（signal、score、provisional、confidence）、analysis_at、data_cutoff_at、quote_at、eligibility的報價兩項狀態與metrics.price。只核對研究參照與報價外框，不計算ETF評分；子類型以etf.md為準，槓反等不支援。不可用validated=true冒充ETF已自動驗證。

### 推導、渲染及定稿

新格式numeric_inputs固定含gate_2、gate_6、gate_7，另保存程式產生的numeric_checks，不把自行填的燈號當作數值證據。範例含完整欄位，按實際資料替換：

- 共用origin為research／provider／missing；quality為exact／approximate／conflicting／unconfirmed，保留as_of、period、reason、source_urls。missing不保留已知數字，unconfirmed或缺必要資料推導白燈。近似／衝突必須提供不同的alternatives原值，逐組判定後取紅、白、黃、綠順序中較不利者；不能只貼近似標籤而保留樂觀燈號。research原值及替代組都須與原檔一致；不同外部原值用provider並附已登錄來源。
- gate_2記current、low／median／high、可核對percentile_pct、reference_price、scenario_price、downside_pct、comparable及sample。當前已知倍數與現價連動研究。股票下行由保守模型價算；股票型ETF由倍數回中位算；債券用已明列情境價格，方向按殖利率判準。research模式另核對股票區間與保守價，provider可補查另一可靠區間／模型但不得改已知當前倍數。現值觀測日須與研究報價日一致，債券對齊持股／殖利率資料日，過期或缺日期為白燈。信用及天期可比性人工確認。
- gate_6記close、SMA20／60／120、RSI14、MACD與訊號、ETF當前premium_pct、參數及人工確認recent_sessions（最多最近3個完成交易日，依序且末日等於quote_context最近完成時點）。觀測日不在此範圍為白燈；同日收盤及ETF當前折溢價須連動研究，research的所有指標另與原檔相符。按本文件含等號與有正負號的乖離判定，ETF另守1%／3%溢價限制。程式不代查交易日曆。
- gate_7股票記前後價格、同口徑前後TTM盈餘／每股淨值原值、可比、近零基期與已確認成長品質問題；current_price及研究已有的current_earnings不可任意另填。window_start／end記同期約12月的觀測日，程式接受364–366日及end=as_of，as_of須與研究報價日一致；其他窗口或日期不形成數值燈號，須人工確認是否真正同期間。已確認成長品質問題仍先紅燈。ETFkind=etf_score、origin=research，其數值point保持null，直接以原研究earnings_support的2／1／0／null推導綠／黃／紅／白，不另重算倍數。

--derive會更新第2、6、7關燈號、numeric_checks、行動及報告雜湊，不修原始數字或來源；原值連動或算術錯誤時拒絕。將新燈號、理由、等待事項與分批前提同步到完整報告後再跑預設驗證。--render使用推導後燈號產生表格；草稿成功不等於定稿通過。第3、4、5、8關及原始證據仍人工。decision-1.0舊檔按原發布組合與assets/decision.schema-1.0.json驗證，不回填numeric_inputs。

```bash
python3 <技能目錄>/scripts/decision_guard.py input.decision.json --research research.json --render
python3 <技能目錄>/scripts/decision_guard.py input.decision.json --research research.json --report final-report.md --derive > derived.decision.json
python3 <技能目錄>/scripts/decision_guard.py derived.decision.json --research research.json
```

--render輸出已推導的行動／條款及八關表片段，作者接在四行摘要與研究結果行後；不替作者編造數字、事件日或批次觸發。--derive推導數值關卡、numeric_checks、conclusion及報告雜湊，不改原檔、不修補原始數字、來源或第3、4、5、8關人工燈號；draft不代表定稿通過。將正確結論反映到行動條件與全文後，必須再跑預設驗證。

定稿保留單一「決策規則版本〔當前rule_version〕」及「行動結論：分批；命中條款：4」（由渲染器填實際值），八關表使用關卡／名稱／燈號／依據四欄且1–8各一行。研究單一結果行須與參照overall一致；全文及表格與結構化紀錄不可矛盾。來源研究版本如與決策版本不同，分別標明，不回填來源。

成功時保留一行「決策驗證範圍：第2、6、7關數值、研究連動及行動結論；其餘關卡與來源證據仍人工核對。」；舊manual_etf再加「ETF研究評分未經程式驗證。」；新etf_snapshot保留原ETF機械驗證範圍行。未執行預設驗證時明列決策結論尚未程式核對，不把--render／--derive的草稿結果當成通過。一般正文的語意、假設合理性及投資勝率不在程式證明範圍。

### 保存

沿用output-and-history的檔名／位置規則，決策定稿在研究檔名基底加.decision後綴，分別保存.decision.md與.decision.json；研究JSON保持其身份，research_reference指向原研究，不批次改寫舊決策或舊分數。若原研究已含本次決策定稿，修改其全文後先重新綁定與驗證研究，再按新檔案雜湊驗證決策。無Python依四條人工核對，明列未完成結論程式驗證；不阻擋資料整理或研究交付。

## 輸出

決策模式保留output-and-history「摘要共同規則」的四行摘要及單一研究結果行，其餘研究內容精簡為一段（五面向燈號、2–3個關鍵數字）；以決策段落取代「下一步觀察」。完整研究可要求展開。以約1,000–1,500字加表格為目標。

1. **標頭**：公司、代碼、報價時間與狀態、研究整體訊號、分析時間。
2. **結論**：進場／分批／等待／放棄＋兩句理由（最支持的證據、最關鍵的限制）。
3. **研究摘要**：四行專家摘要＋單一研究結果行＋精簡研究段落；行動結論另標，不冒充研究燈號。
4. **八關檢核表**：關卡、燈號、一句證據。
5. **行動條件**：分批各批觸發條件或等待事項；升級與降級條件。
6. **退場條件**：論點型、價格型、時間型。
7. **最可能錯在哪裡（決策層反方審查，R9）**：假設本次結論是錯的，列最可能的3個原因，逐一說明是否已揭露或反映在燈號，並指出最弱的一環及其錯誤時結論如何改變。未處理者須修正後再交付。
8. 一句「研究判斷，非個人化投資建議」及上方定稿驗證範圍；未執行時明列未核對，不宣稱已通過。

重要數據與事件就近引用來源。

## ETF版關卡改寫

標的為ETF時，八關架構、燈號定義、結論規則與輸出格式不變，只改寫下列關卡；未列出的關卡照原規則。槓反、期貨、商品、加密資產ETF不進決策層。

| 關卡 | ETF版判準 |
| --- | --- |
| 2 估值紀律 | 股票型用底層P/E（或P/B）位置及倍數回到中位時的跌幅。按序：已確認上緣20%／高於高點或回中位跌幅>30%🔴；缺可靠區間或回中位計算⚪；低於中位且樣本達門檻🟢；其餘🟡，短樣本最高🟡。區間邊界依原第2關。債券型另按下段，不能把高殖利率套成股票估值紅燈。 |
| 3 持有理由可驗證 | ETF沒有公司論點，改評持有理由。🟢 至少2項可量化理由（成分股加權盈餘成長、配息來源比例、追蹤差距、產業指標等）且有資料可持續追蹤；🟡 只有1項；🔴 主要依賴題材、市場情緒或「長期會漲」；⚪ 研究層未形成理由。 |
| 4 市場環境 | 跨境ETF改看成分股所在市場的指標。 |
| 5 事件風險 | 事件改為：換股審核公告與生效日、除息日、權重前三大成分股的財報或法說會、追蹤指數方法變更。 |
| 6 價格位置與動能 | 原判準外加折溢價限制：進場時溢價>1%本關最高🟡，>3%為🔴。 |
| 7 預期反映程度 | 直接沿用研究層earnings_support分數：2分🟢、1分🟡、0分🔴、null⚪，不重算。 |

資料來源對照：第2關沿用估值面向與band_position；第3關沿用持股結構與配息品質證據；第7關沿用earnings_support；其餘同個股版。

債券型第2關：先核對信用與天期可比性、歷史到期殖利率區間及明列利率情境的價格敏感度（見etf.md子類型調整）；已確認情境下行>30%🔴；缺必要資料⚪；殖利率高於中位、樣本達門檻且情境下行≤15%🟢；其餘🟡。殖利率恰為中位為🟡，不以股價／殖利率倍數公式代算。

### 核心長抱型ETF補充

僅適用寬基市值型ETF（子類型為市值型），主題型、高股息型、主動式不適用。

- 結論為「分批」時，可寫成定期定額節奏與恢復單筆的條件，例如「每月固定日買入，至加權P/E回到區間中段後恢復單筆」，不寫金額或比例。
- 第8關的價格型條件維持原規則。只有使用者主動提供自己的目標配置時，才可另加一段「再平衡觸發條件」，寫成偏離幅度的判定方式；此段不影響燈號與結論，也不建議配置比例。
